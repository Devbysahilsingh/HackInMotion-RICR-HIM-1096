# Market Data Normalization

Pipeline per fetched row (job code `backend/src/jobs/market-refresh`):
1. **Parse & type:** prices → int ₹/quintal; arrival_date → ISO date (DD/MM/YYYY source format); trim/collapse whitespace.
2. **Sanity gates:** 0 < price < 100,000; modal ∉ [min,max] → clamp to nearest bound + `flagged:true`; date > today or < 90d ago → drop (counter).
3. **Canonicalize:** commodity → cropCode via alias map from `cropRegistry.market.aliases` (miss → drop+count, with up to 10 distinct sample strings kept — the count says something broke, the samples say what); state/district/market whitespace-normalized and required non-empty (else `dropped.badGeo`); market name trimmed as-is (display value).
   - **Deliberate deviation:** this step originally specified state/district fuzzy-matched ≥0.9 against a canonical list in `shared/constants/geo`. **That module does not exist.** Inventing a states-and-districts gazetteer to match against would fabricate reference data (rule 7), and dropping every row for want of one would discard the entire feed. So geography is normalized and required to be present, but not gated against a canonical list; `dropped.badGeo` counts only structurally unusable values. P1-5 hit the identical absence in farm validation and resolved it the same way — an invented list would be worse than a late one. Populating `shared/constants/geo` remains an open task, and both call sites tighten when it lands.
4. **Dedupe/idempotency:** unique index (commodityCode, market, date); re-runs upsert identical rows harmlessly.
5. **Job report:** {fetched, inserted, duplicates, dropped:{unmapped, badDate, badPrice, **badGeo**}, droppedTotal, dropRate, flagged, unmappedSamples, ok, durationMs} → pino log + `/healthz` job state. The fourth drop bucket was missing: the pipeline names four drop causes but the report shape published only three, so `badGeo` rows disappeared from the drop-rate arithmetic that the 30% schema-drift guard depends on.
6. **`flagged` is now a stored field** on `marketPrices` (docs/database/schema.md), not just a job counter — a clamped modal price must remain distinguishable from a published one at read time, not only at ingest time (honesty rule 9).
Quarantine philosophy: bad rows never enter history; drop-rate >30% aborts the batch (schema-drift guard) keeping prior data intact.
