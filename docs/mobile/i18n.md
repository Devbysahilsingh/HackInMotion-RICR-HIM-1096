# Mobile i18n

Same architecture as web (docs/i18n/): i18next initialized from **shared/i18n** resources (metro watchFolders `../shared`; resolver documented in mobile README at scaffold); language: first-run screen → users.language sync on login → AsyncStorage persistence for pre-auth screens; device-locale default (hi→Hindi).
Mobile-specific requirements: permission rationale strings (camera/mic/location) localized incl. the OS-level strings via app.json `locales` config (Android per-locale resources); TTS `language:'hi-IN'` matched to UI language; Devanagari rendering verified on low-end Android (system fonts fine; test task Day 2); date/number Intl polyfill if Hermes lacks full ICU (`@formatjs` polyfills — decision at scaffold, noted); text-scaling tolerance to 1.3× (accessibility).
Parity gate + human-verification workflow identical (docs/i18n/translation-strategy.md) — one translation tree serves both surfaces by construction.
