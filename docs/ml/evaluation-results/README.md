## The field-test number — read this before quoting any accuracy figure

**In-domain accuracy 0.9632. Field accuracy 0.1257.** Chance over 35 classes is
0.029, so unmasked field performance is barely above chance. Under declared-crop
masking — the production condition — it is 0.3333.

Two macro-F1s are published because one number cannot honestly serve both
purposes. Only **13 of 35 classes** appear in PlantDoc, so macro-F1 over all 35
is mechanically capped near 13/35 and reads 0.0564; over the classes actually
present it is 0.1517. Neither is flattering and neither is hidden.

Per-class field recall ranges from **0.00** (TOMATO_MOSAIC_VIRUS, TOMATO_HEALTHY)
to **0.37** (MAIZE_GRAY_LEAF_SPOT).

This is the documented PlantVillage risk arriving exactly as predicted: the
training corpus is lab imagery, PlantDoc is field imagery, and the model has
largely learned the former's domain. `docs/ml/evaluation-plan.md` set no numeric
gate on this figure precisely so that it would be published rather than
suppressed — but it means **no field-robustness claim can be made for this
model**, and the product's reliance on the Gemini tier for real-world photos is
not a fallback detail, it is load-bearing.

## Mandatory confound disclosures

### RICE_NORMAL ↔ RICE_BROWN_SPOT

Required by `datasets/manifest.json` to be reported explicitly rather than
folded into macro-F1, because the two classes come from disjoint sources
(studio vs field, separable at 0.96) and are therefore decidable by background
alone. Test split:

- RICE_NORMAL recall **1.0000** (82 samples), RICE_BROWN_SPOT recall **1.0000** (91 samples)
- RICE_NORMAL → RICE_BROWN_SPOT: **0 of 82** · RICE_BROWN_SPOT → RICE_NORMAL: **0 of 91**

The manifest's instruction is: "If RICE_NORMAL recall exceeds RICE_BROWN_SPOT
recall by a wide margin, treat it as evidence of the shortcut, not of skill."
There is no margin — but that is not reassurance. **Two classes drawn from
disjoint sources that are separable at 0.96 from background alone have been
separated perfectly, with zero confusion in either direction.** Flawless
separation of a source-disjoint pair is precisely the signature the shortcut
would produce; it is weaker evidence of skill than an imperfect result would
have been.

Both numbers are in-domain, and neither says anything about healthy-rice
performance in a field photograph, which remains **unvalidated** — RICE_NORMAL
is 100% studio imagery (ADR-021 decision 2). PlantDoc contains no rice, so the
field test cannot speak to this either.

### Chilli source confound

`CHILLI_ANTHRACNOSE` exists only in `chilli_secondary`; `CHILLI_BACTERIAL_SPOT`,
`CHILLI_NUTRIENT_DEFICIENCY` and `CHILLI_POWDERY_MILDEW` only in
`chilli_primary`, and the two sources are separable at 0.91 from a single
background statistic. Their test metrics are in `evaluation.json` and are
**not evidence of disease-discrimination ability**. The Grad-CAM probe required
before publishing any chilli figure has been run — see below.

## Grad-CAM background-reliance probe (P4-8)

20 samples per split/crop, Grad-CAM over the final conv stage. The metric is the
share of attention mass in the outer 25% border ring. **It is a proxy**: this
corpus has no leaf segmentation masks, so "lesion or bench?" cannot be answered
exactly. Uniform attention scores 0.750, so that is the reference, not zero.

| Split | Crop | Border mass | Ratio to uniform |
|---|---|---|---|
| test | CHILLI | 0.662 | 0.88 |
| test | RICE | 0.655 | 0.87 |
| test | COTTON | 0.683 | 0.91 |
| test | MAIZE | 0.731 | 0.97 |
| test | POTATO | 0.731 | 0.97 |
| test | **TOMATO** | **0.867** | **1.16** |
| fieldtest | MAIZE | 0.682 | 0.91 |
| fieldtest | POTATO | 0.687 | 0.92 |
| fieldtest | TOMATO | 0.710 | 0.95 |

**Chilli attention is centre-weighted (0.88 of uniform)**, so this probe does not
show background reliance for chilli — which satisfies the gate to publish chilli
figures. It does **not** clear the source confound itself, which is a property of
the data, not of where the model looks; that remains contained, not solved.

**TOMATO is the one crop above uniform (1.16)** — attention skewed toward the
border on in-domain images. Tomato is the largest PlantVillage group (10 classes,
~17k images) and this is consistent with background reliance on lab imagery. It
is also the crop with the largest field-test population, whose recalls run
0.00–0.27.

## Threshold decision — RESOLVED 2026-08-13

`calibrate.py` derived **τ = 0.00** and **τ_healthy = 0.00**, and both are
correct applications of the documented criteria:

- τ: "precision-of-accepted ≥ 0.90 while maximizing coverage" — precision at
  threshold 0 is already 0.9654, so the maximum-coverage answer is 0.00.
- τ_healthy: "false-negative-disease rate among accepted-healthy ≤ 5%" — that
  rate at threshold 0 is already 0.0098.

The criteria are **non-binding** for a model this accurate. The rule was written
to *floor quality*, on the assumption that abstention would fall out of the
floor being binding; here it does not. `confidence-strategy.md` anticipated
0.70–0.80 while also saying "final value = data's answer", and the data's answer
is degenerate.

**Shipped: τ = 0.70, τ_healthy = 0.80** — a recorded product decision on top of
the measurement, declared in `config.yaml` under `calibration.policy_override`
and re-validated by `calibrate.py` against every documented criterion before it
is accepted (an override failing any check is refused, not warned about).

| Validation check | Measured | |
|---|---|---|
| precision-of-accepted ≥ 0.90 | 0.9851 | PASS |
| healthy false-negative rate ≤ 0.05 | 0.0037 | PASS |
| τ_healthy > τ ("stricter") | 0.80 > 0.70 | PASS |
| healthy-class recall ≥ 0.90 @τ_healthy | 0.9518 | PASS |
| confidence branch reachable | τ = 0.70 > 0 | PASS |
| healthy branch reachable | τ_healthy = 0.80 > 0 | PASS |

### Why these values

The **healthy-recall ship gate** is the constraint that actually binds
τ_healthy, and it had not been measured before this decision:

| τ_healthy | min healthy recall (val) | |
|---|---|---|
| 0.80 | 0.9518 | PASS |
| 0.85 | 0.9157 | PASS |
| 0.90 | 0.8434 | **FAIL** |
| 0.95 | 0.8193 | **FAIL** |

τ_healthy ≤ 0.85 is therefore a hard ceiling, and "stricter" makes τ < 0.85 —
which **eliminates τ = 0.90 by measurement**, since it would require
τ_healthy > 0.90 and every such value fails the gate.

τ = 0.70 is the smallest value satisfying every requirement, so it maximises
coverage as the rule asks. τ_healthy = 0.80 is preferred over 0.85: identical
false-negative protection (0.0037 vs 0.0038) with materially better healthy
recall (0.9518 vs 0.9157).

**Decisive evidence that the branch was dead at τ = 0.00** — at τ = 0.70 the
validation rejections split as:

- rejected by the τ branch alone: **142**
- rejected by the margin guard alone: **0**
- rejected by the healthy guard alone: 5
- total abstained: 248 / 5811

The margin guard uniquely rejects **nothing**. At τ = 0.00 it was the only live
guard, so "Never force a prediction" was resting entirely on a leg that
contributes no unique rejections.

### Trade-off

Coverage 0.9835 → **0.9573** (≈2.6 points more escalation to the Gemini tier,
negligible against a 10/day/user cap and a 1,500/day free tier), in exchange for
precision of accepted 0.9731 → **0.9851** and the false-negative-disease rate
halved (0.0074 → 0.0037). Test split confirms it generalises: coverage 0.9617,
precision 0.9827, min healthy recall 0.9512.

**Caveat:** the healthy-recall gate is driven by small classes — POTATO_HEALTHY
has 23 validation samples and COTTON_HEALTHY 38, so one image moves the minimum
by ~4 points. τ_healthy = 0.90 failing on validation (0.8434) while passing on
test (0.9146) is exactly that noise. Validation governs, per the doc.

`calibration.json` stores both `derivedThresholds` (what the data said) and
`thresholds` (what ships), so the measurement is never overwritten by the
decision made on top of it.
