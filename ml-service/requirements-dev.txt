# Test tooling only. NEVER installed into the runtime image — the Dockerfile
# installs requirements.txt alone, so nothing here reaches production.
#
# Both additions are beyond the locked ml set in
# docs/security/dependency-security.md and are justified as dev-only:
#
#   pytest — the repo already mandates a pytest suite for ml-service
#            (docs/testing/ml-testing.md). There is no stdlib equivalent with
#            fixtures and parametrisation, and unittest would make the contract
#            suite materially harder to read.
#   httpx  — a hard requirement of fastapi.testclient.TestClient. Without it the
#            API contract could only be tested by starting a real server and
#            talking to a socket, which is slower and flakier for no gain.
#   pip-audit — the Python half of the dependency gate that
#            docs/security/security-testing.md already mandates ("npm
#            audit/pip-audit"). Pinning it here means the gate is reproducible
#            rather than depending on whatever a developer happens to have
#            installed globally. Run: `python -m pip_audit -r requirements.txt`.

-r requirements.txt

# ruff:      the Python linter, pinned like everything else here. Chosen over
#            Flake8 (plugin matrix, four config files) and Pylint (slow, opinion
#            -heavy) because it is one binary with no plugins and it already
#            understands the `# noqa: BLE001` / `# noqa: E402` codes this source
#            was annotated with before any linter ran. Dev-only: it is not in
#            requirements.txt and never reaches the runtime image.
#            Run: `python -m ruff check .`  (config: pyproject.toml [tool.ruff])
